# منصة مانارا الرياضية — دليل شامل

**منصة تربط الرياضيين الشباب بالأندية والأكاديميات** في كل الرياضات، بدعم كامل للعربية (RTL) والإنجليزية، وقابلية تثبيت كتطبيق PWA.

- **التقنيات:** Node.js / Express (خادم) + HTML / CSS / JavaScript خام + Bootstrap 5 (واجهة)
- **التشغيل:** `npm start` داخل مجلد `server/` → يعمل على `http://localhost:5000`
- **قاعدة البيانات:** MongoDB Atlas عند التوفر، مع احتياط تلقائي لملف JSON محلي (`server/data/db.json`)

---

## 1. البنية المعمارية

```
Manara/
├── roster/            # الواجهة الأمامية (صفحات + JS خام + Service Worker)
│   ├── js/api.js      # عميل API موحّد (كل الطلبات تمر منه)
│   ├── js/*.js        # منطق الصفحات (ملفات، رسائل، إدارة...)
│   └── *.html         # الصفحات (عربية RTL)
└── server/            # الخادم الخلفي
    ├── server.js      # نقطة الدخول (تشغيل + بذر البيانات + أدمن)
    ├── src/app.js     # إعداد Express (أمان، حدود، مسارات، ملفات ثابتة)
    ├── src/db.js      # طبقة البيانات (Mongo مع احتياط JSON)
    ├── src/routes/    # مسارات API (auth, players, clubs, messages, uploads, subscription, admin...)
    ├── src/middleware/# مصادقة JWT + حدود معدلات + فلاتر رسائل
    └── test/          # سويتات اختبار (E2E + وحدة)
```

**تدفق البيانات:** الواجهة تتحدث مع الخادم عبر `/api/*` فقط (`api.js`)، والخادم يقرأ/يكتب في قاعدة البيانات، ويخدم الملفات الثابتة من `roster/` والوسائط من `/uploads/`.

## 2. المزايا (ما تعمله المنصة)

### 2.1 الحسابات والتحقق
- تسجيل لاعب أو نادٍ **بمراجعة إدارية بشرية**: يجب رفع وثائق رسمية (شهادة ميلاد + تقرير طبي + إقرار للاعب؛ خطاب رسمي + رخصة للنادي) قبل تفعيل الحساب.
- **تحقق من البريد الإلكتروني عبر رمز OTP** (6 أرقام، 15 دقيقة، حد 5 محاولات).
- مصادقة **JWT** (7 أيام) + قفل الحساب بعد 5 محاولات دخول فاشلة.
- لوحة إدارة لمراجعة الطلبات (قبول/رفض مع سبب + مهلة 15 دقيقة لإعادة المحاولة).
- استعادة كلمة المرور برمز يُرسل للبريد (استخدام لمرة واحدة).

### 2.2 البحث والتصفح
- لوحة لاعبين بفلاتر (رياضة، مركز، بلد، مستوى، توافر) وترتيب (الأحدث/الاسم/التقييم) وصفحات.
- لوحة أندية بفلاتر وبحث.
- **حماية الخصوصية**: القوائم العامة تُظهر بيانات محذوفة (بدون هاتف/بريد/واتساب/مستندات)؛ الزائر غير المالك يرى بيانات تواصل مقنّعة (`012*****67`) والمستندات محجوبة.
- إحصاءات حية (عدد اللاعبين، الأندية، الرياضات، الدول) على الصفحة الرئيسية.

### 2.3 الملفات الشخصية
- ملفات عربية كاملة: نبذة، فيديوهات، إحصائيات، معلومات سريعة، تواصل، تقييمات.
- **تقييم نجوم (1-5) من الأندية** — تقييم واحد لكل نادٍ، يُعاد احتساب المعدل تلقائيًا.
- **قائمة مختصرة (Shortlist)** + **ملاحظات سكاوت خاصة** لكل نادٍ + جدول مقارنة.
- **عدّاد "من شاهد بروفايلك"** (آخر 60 مشاهدًا، معرّفون بالدور والنادي).

### 2.4 التواصل
- رسائل داخلية بين الأندية واللاعبين بقواعد صارمة: **النادي فقط يبدأ المحادثة**، اللاعب يرد فقط على من راسله، و**حظر طلب بيانات التواصل** (أرقام، إيميلات...) داخل الرسائل.
- شارة رسائل غير مقروءة + تحديث دوري.
- طلبات توظيف (Transfer / Tryout / Scout) من الأندية للاعبين، بحالات (قيد الانتظار/مقبول/مرفوض/منجز).

### 2.5 رفع الملفات والوسائط
- رفع متعدد مع **قائمة بيضاء MIME** (صور، PDF، صيغ فيديو الجوال: MOV/3GP/M4V/MKV...) وحدود حجم.
- **تحقق تلقائي من فيديوهات اللاعبين**: المدة (5-15 دقيقة) + فحص علامات التعديل.
- **ضغط الفيديو في الخلفية** (H.264 ~720p) + استخراج صورة مصغرة (FFmpeg) بنفس الرابط.
- ضغط الصور، مع استثناء **إيصالات الدفع** (تبقى بلا مساس للفحص الجنائي).
- حماية `/uploads` الذكية: الملفات العامة تُخدم مباشرة، بينما **المستندات الرسمية والإيصالات خاصة** (المالك + الأدمن فقط).

### 2.6 الاشتراكات والدفع (SaaS)
- خطتان: لاعب **39 ج.م/شهر**، نادٍ **299 ج.م/شهر** + **فترة تجريبية مجانية** (لاعب: يومان، نادٍ: 7 أيام).
- دفع عبر المحافظ المصرية (فودافون كاش / فوري) برفع صورة الإيصال.
- **تحقق تلقائي من الإيصالات**: فحص تلاعب (forensics) + OCR لاستخراج (المبلغ/التاريخ/المرجع/المستلم) + مطابقة مع أرقام منارة + كشف التكرار، ثم موافقة تلقائية أو تحويل لمراجعة يدوية.
- إدارة اشتراك: إلغاء التجديد، استئناف، رسائل تجديد، تذكيرات انتهاء الفترة.
- **مساعد ذكي (AI)** للاعبين/الأندية — رد اللاعب غير المشترك يُحجز حتى دفع الفاتورة.

### 2.7 خزنة الإقرارات المشفرة
- عند الموافقة على لاعب، تُخزَّن نسخة من صورة الإقرار **مشفّرة AES-256-GCM** (مفتاح من عبارة سرية ثلاثية عبر scrypt) في `server/declarations/`، لا يُخدمها الويب إطلاقًا — يفتحها الأدمن فقط عبر بوابة عبارة سرية بجلسة 15 دقيقة.

### 2.8 الحماية التقنية
- رؤوس أمان (helmet)، منع حقن NoSQL + تلوث معاملات HTTP.
- **حدود معدلات** لكل نقطة حساسة (دخول، تسجيل، رفع، دفع...) بمفاتيح IP أو مستخدم.
- قوائم بيضاء للحقول (ضد Mass Assignment) في كل PUT/POST.
- معالج أخطاء لا يكشف تفاصيل داخلية للعميل.
- مفاتيح سرية إلزامية في الإنتاج (`JWT_SECRET`, `ADMIN_PASSWORD`, `VAULT_PASSPHRASE`) مع توليد عشوائي في التطوير.
- PWA (Service Worker) بوضع عدم اتصال + تصميم متجاوب + `prefers-reduced-motion`.

## 3. العيوب والقيود المعروفة

### 3.1 تخزين البيانات
| العيب | التفاصيل |
|-------|----------|
| **كتابة JSON متزامنة** | `fs.writeFileSync` يوقف event loop عند كل حفظ — مقبول للتطوير/محلي، غير مناسب لإنتاج عالي الضغط. |
| **مزامنة MongoDB ضعيفة** | عند اتصال MongoDB، يتم مسح وإعادة إدراج كل المجموعات كاملةً كل 5 ثوانٍ — خطير للبيانات الحقيقية، ولا يُنصح به فوق حدود صغيرة. |
| **اتصال MongoDB يفشل SSL في البيئة الحالية** | يقع الخادم على احتياط JSON تلقائيًا (مشكلة بنية تحتية، ليست كودًا). |
| **لا توجد آلية قفل** | طلبات متزامنة قد تتداخل على الملف (فقدان بيانات) في حالات نادرة. |

### 3.2 أمان (تصميمات متوسطة الخطورة)
- **JWT في localStorage** — عرضة لسرقة الرمز إذا ظهرت ثغرة XSS؛ الحل الأفضل httpOnly cookies.
- **CORS افتراضي `*`** — يجب تقييده في الإنتاج عبر `CORS_ORIGIN`.
- **حدود المعدلات في الذاكرة** — لكل عملية خادم؛ لا تصلح للتوسع الأفقي (تحتاج Redis).
- **`userId` الداخلي مكشوف في القوائم العامة** — يسمح بتعيين الحسابات ومراسلة أي مستخدم مباشرة (بعد اشتراك النادي).

### 3.3 واجهة وتجربة مستخدم
- **بيانات تجريبية ثابتة داخل HTML** كتصميم احتياطي — إذا تعطل API قد تظهر للمستخدم كبيانات حقيقية (أُصلح للفشل لكن الصفحة المفتوحة لأول مرة بدون JS تعرضها).
- **لا إشعارات فورية** — رسائل بتحديث دوري (polling).
- **لا حذف/تعديل رسائل**، ولا مرفقات داخل المحادثة، ولا بحث في الرسائل.
- تصفح ملفات اللاعبين/الأندية **يتطلب تسجيل دخول** — يقلل التسويق العام لكنه قرار أمني مقصود.
- المحادثات الطويلة (>50 رسالة) تستهلك طلبات متعددة لجلب كل الصفحات.

### 3.4 تبعيات خارجية
- **FFmpeg** مطلوب لضغط الفيديو والصور المصغرة (موجود في `%LOCALAPPDATA%\Programs\ffmpeg\...` على هذا الجهاز — غيابه يبطل الضغط بصمت).
- **Tesseract.js** للـ OCR — حميل نسبيًا، والدقة تعتمد على جودة صورة الإيصال.
- **البريد** في التطوير عبر Ethereal (لا يصل فعليًا) — الإنتاج يتطلب SMTP حقيقي.

### 3.5 جودة البرمجيات
- **لا Lint/Formatter** (ESLint/Prettier) — الشيفرة بلا فحص أسلوب آلي.
- **لا CI/CD** — الاختبارات يدوية محليًا.
- **سويتات الاختبار E2E تحتاج**: سيرفر يعمل على :5000 + حساب أدمن (كلمة مرورها مكتوبة داخل الملفات وغير متزامنة مع `.env` — شغّلها بـ `ADMIN_PASSWORD` مؤقت) + ملف فيديو fixture + أنظمة الرفع الحقيقية.
- **تلوث حالة الاختبارات**: حد الدفع (5/ساعة/IP) يجعل تشغيل عدة سويتات متتالية يفشل — أعد تشغيل السيرفر بين السويتات.
- **بدون توثيق API** (Swagger/OpenAPI).

## 4. التشغيل

```bash
cd server
npm install        # تثبيت الاعتماديات
npm start          # تشغيل على http://localhost:5000
```

**الإعداد المطلوب (`.env`):**

| المتغير | الوصف |
|---------|-------|
| `JWT_SECRET` | مفتاح توقيع الرموز (إلزامي في الإنتاج) |
| `ADMIN_PASSWORD` | كلمة مرور حساب الأدمن `admin@manara.app` |
| `MONGODB_URI` | اختياري — رابط Atlas (يُستخدم احتياط JSON إذا فشل) |
| `SMTP_HOST/USER/PASS` | اختياري — بريد حقيقي في الإنتاج |
| `VAULT_PASSPHRASE` | العبارة السرية الثلاثية للخزنة (إلزامي في الإنتاج) |
| `CORS_ORIGIN` | تقييد النطاقات المسموحة في الإنتاج |
| `MANARA_WALLETS` | أرقام محافظ منارة للتحقق التلقائي من الإيصالات |

**حساب الأدمن:** يُنشأ تلقائيًا عند أول تشغيل.
